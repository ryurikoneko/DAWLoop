# Desktop Preview 更新通知批准

本次批准仅适用于 `dawloop-desktop / v0.5.6-alpha.2 / preview`，Release ID 为 `412979500`。独立批准原件见 [Alpha.2 批准记录](approvals/alpha2-preview-20261015.json)，有效期由记录中的 UTC 时间决定，七日后自动到期；不得自动续期或继承给未来版本。

维护者于 2026-10-15 明确声明已完成 Windows 通知人工测试并批准上线。这是维护者确认，执行代理没有直接观察该轮系统操作；逐项系统通知权限和勿扰模式结果未单独提供，不填造逐项 PASS。

## 客户端范围

客户端运行时或下次检查时，读取官方 Release 与本仓库 main 的 `release_notification.json`。用户必须启用更新检查、选择 Preview，且已安装版本低于 Alpha.2，才有主动应用内提示资格。Windows Toast 还须用户主动开启通知，并受 Windows 自身设置控制。默认 Stable 用户不会收到 Preview 提醒，同版本和更高版本不会收到无意义升级提醒。

Alpha.1 已含 schema v2 更新客户端，可消费本批准；更早的内部候选需以实际更新模块为准。没有更新模块的旧客户端无法通过远端配置补装该功能。软件关闭时不检查，不新增自启动、常驻服务或后台代理。

已发布 Alpha.1/Alpha.2 使用各自内置的简短 Toast 文案，不读取批准记录的 `requested_content`。本次将维护者指定的中英文标题与正文原样登记，但不能宣称旧客户端已自动更新文案。当前版本不会下载、安装或替换程序。

## 去重与撤销

同一 Release ID 与版本的 Toast 去重状态落盘，稍后提醒遵循现有七日冷却。远端批准缓存最长五分钟；刷新失败即关闭主动提醒。发布信息检查可使用二十四小时缓存，仍须新鲜批准才能提醒。撤销不承诺在离线客户端即时生效，也不会强制删除已送达的 Windows 通知。

紧急撤销时，通过正常 PR 将根清单 `notification_enabled` 和 `approved_by_owner` 设为 false，并在 `revocations` 追加本次 `approval_id`，保留原批准及历史记录。客户端下一次成功读取配置后拒绝新通知；五分钟批准时效也会阻止离线复用。重新开启或延长时效需要维护者重新授权。

未增加送达追踪、设备身份或音乐/工程/模型数据采集；不能由配置已上线推导所有旧用户已收到提醒。
